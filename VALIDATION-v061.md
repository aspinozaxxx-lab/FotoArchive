# FotoArchive 0.6.1 — PSD и служебные файлы macOS

В ходе наблюдения за настоящей индексацией обнаружены четыре AppleDouble-файла с расширением PSD и один настоящий 16-битный PSD, который Pillow не распознавал. Исправлено определение служебных файлов по имени `._…` и сигнатуре AppleDouble; настоящий снимок с таким префиксом остаётся изображением. Существующие ошибочные записи скрываются и исключаются из очереди через обычный outbox. Оригиналы не перемещаются, не удаляются и не записываются. Недоступный файл не исключается; проверка повторяется при следующем запуске.

Для PSD/PSB используется сохранённое сведённое изображение через psd-tools 1.19.0, с пропуском большого блока слоёв по смещению. Поддержаны RAW/RLE/ZIP/ZIP-prediction сжатие, 8/16-битные изображения, EXIF, ориентация, XMP GPS и преобразование ICC в sRGB. Чтение мест использует только метаданные. Слои не пересчитываются; при отсутствии сохранённого сведённого изображения показано объяснение. Декодирование ограничено бюджетом 512 МиБ на документ. Успешные задания не сбрасываются, ранее не прочитанные PSD повторяются автоматически один раз при обновлении декодера.

Настоящий PSD размером 379 279 332 байта открылся за 1,04 с после чтения файла для контрольной суммы (прогретый кэш ОС). Размер 3456 × 5184, дата 14.12.2011 08:49:50 и камера Canon EOS 60D прочитаны; SHA-256 до и после совпал. Проверка изображения выполнена визуально. Время не является оценкой чтения с холодного HDD.

Целевые проверки: 33 теста прошли, включая все четыре варианта сжатия при глубине 8/16, PSB, сохранение даты и ориентации, GPS, пропуск заведомо неразбираемого блока слоёв, миграцию ошибочных sidecar-записей и неизменность оригиналов. Полная проверка и готовый EXE фиксируются ниже после выполнения.

Источники: [AppleDouble, RFC 1740](https://www.rfc-editor.org/rfc/rfc1740), [psd-tools: сохранённое изображение и метаданные](https://psd-tools.readthedocs.io/en/latest/reference/psd_tools.html).
