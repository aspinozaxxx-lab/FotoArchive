# FotoArchive 0.6.3 — отзывчивость каталога

При переключении между фото и видео запрос первой страницы мог читать и сортировать полные метаданные всего архива. На текущем каталоге из 126 546 файлов (126 263 доступны для просмотра) первая страница фото занимала 10,18 секунды, общий список — 10,24 секунды. Запрос выполнялся на том же координаторе, что и фоновое распознавание; устаревшие запросы после переключений также оставались в очереди.

Исправления:

- Страницы читаются в порядке сохранённой выдачи с выборкой только нужных записей. Порядок страниц и сохранение позиции при обновлении библиотеки остаются прежними.
- Обычные фильтры и страницы обслуживает отдельный поток со своим соединением SQLite в режиме `mode=ro`. Он не загружает модели, не пишет в основной каталог и не ждёт координатора GPU.
- Новое переключение заменяет ожидающее и прерывает устаревший SQL. Очередь страниц ограничена восемью запросами.
- Координатор пропускает устаревшие запросы поиска и определения лиц для уже оставленных снимков. Задания индексации, команды изменения библиотеки и подтверждённые операции поворота сохраняются.

Проверки:

- 148 тестов прошли за 16,37 секунды, включая чтение при занятом писателе SQLite, отмену длительного SQL, быстрые переключения, запрет записи через читающее соединение, независимость Backend от занятого координатора, стабильные страницы и актуализацию библиотеки.
- Read-only замеры на текущем каталоге при работающей прежней версии: создание списка фото 0,51 секунды; первая страница 0,0037 секунды; последняя страница 0,27 секунды. Видео: создание списка 0,34 секунды, первая страница 0,0125 секунды.
- Серия из 12 переключений в исходной версии исправления: p95 после первого запуска 0,96 секунды. Последнее из 50 быстрых переключений получено за 0,34 секунды.
- Измерения относятся к получению записей для интерфейса; загрузка миниатюр, запуск модели и смысловой поиск измеряются отдельно. Новые модели и исходные материалы при этой диагностике не изменялись.
