# FotoArchive

Локальный каталог фотографий и видео для Windows 11 x64. Поиск по русскому запросу, похожим кадрам и лицам, ползунок дат, бесконечная прокрутка и проверка сложных условий на AMD GPU.

Версия **0.8.1**: панель «Обработка» сравнивает компьютер и сервер по одинаковым этапам и темпу за последнюю минуту. Отдельно показаны очередь, завершённые и сохранённые задания, текущая передача и накопленный трафик, заполнение дискового кэша из 20 ГБ и ресурсы GPU. Приём результатов работает независимо от отправки снимков; очередь автоматически пополняется большим запасом. [Проверки](VALIDATION-v081.md), [устройство серверной обработки](server/README.md), [каталог](CATALOG-v070.md).

Исходный код: [aspinozaxxx-lab/FotoArchive](https://github.com/aspinozaxxx-lab/FotoArchive), основная ветка `main`. Репозиторий содержит приложение, тесты и сборку; модели, личные медиа и рабочие базы хранятся отдельно.

## Запуск

Откройте `dist\FotoArchive\FotoArchive.exe`. Python устанавливать не требуется. Папку приложения нужно переносить целиком, вместе с `_internal`.

Иконка встроена в EXE и используется окном и панелью задач Windows. Исходник PNG, ICO с размерами от 16 до 256 пикселей и описание оформления находятся в `fotoarchive/assets` в проекте, в поставке — в `_internal/fotoarchive/assets`.

Данные каталога и модели находятся отдельно в `D:\FotoArchiveData`. На этом компьютере исходный источник — `F:\MyFoto`, подключены папки `2003`–`2022`, индексация продолжается. Список хранится в `settings.json` и сохраняется при обновлении приложения. Индексация и поиск читают оригиналы. Изменение исходного файла происходит только при применении выбранных поворотов; перед этим сохраняется точная резервная копия.

- **Найти:** введите описание на русском. Поиск использует **визуальные эмбеддинги фотографий**, а также описания, имена файлов и географический контекст. Результаты подгружаются при прокрутке без ограничения в 200 снимков. Это ранжирование по близости: дальние результаты могут не соответствовать запросу.
- **Показывать:** над сеткой находятся «Все», «Фото», «Видео». Они работают вместе с датой, папкой, форматом, камерой, текстовым запросом и поиском человека.
- **Видео:** в каталоге показана одна карточка файла, для найденного совпадения указано время. Двойной щелчок открывает встроенный плеер с этого момента: воспроизведение, пауза, перемотка и стандартное разворачивание окна. «Найденный кадр · лица» открывает статичный кадр для увеличения и поиска человека. Индексируются кадры через 10 секунд по всей длительности без ограничения на первые минуты; короткие события между кадрами могут быть пропущены. Проверка условий относится к выбранному кадру, а не ко всему ролику. Звук и речь пока не индексируются.
- **Проверять условия на фото:** проверка количества, действий и исключений. Условия показаны над результатами; группы «Подходят», «Неясно» и «Не подходят» разделяют выводы модели. Проверяется порция из 40 кандидатов; продолжение — кнопкой «Проверить ещё 40». Непроверенные результаты не считаются подтверждёнными.
- Длинная проверка подгружает следующих кандидатов порциями. Результаты групп хранятся в SQLite и подгружаются при прокрутке. В памяти окна остаются не более 8 блоков по 200 записей и 256 миниатюр; очередь проверки — до 40 снимков. Возврат к началу подгружает вытесненные блоки.
- **Плавная прокрутка:** одно деление колёсика слегка сдвигает сетку, быстрое вращение ускоряет движение. Обратное вращение сразу меняет направление. Полоса прокрутки и клавиши сохраняют обычное управление; тачпад передаёт движение непосредственно. Следующая страница запрашивается заранее, когда до края остаётся около двух экранов.
- **Найти человека:** нажмите на лицо в большом просмотре или в панели справа. Появится панель фильтра с выбранными примерами лиц и кнопкой **«Сбросить поиск по человеку»**. Повторное нажатие на лицо того же человека добавляет ещё один ракурс. **«Добавить пример из каталога»** временно показывает фотографии вне фильтра человека, сохраняя примеры и остальные фильтры. Удалить ошибочный пример можно кнопкой ×. Совпадения по всем примерам объединяются; каждая фотография показана один раз, по лучшему совпадению. Примеры и исключения сохраняются при перезапуске.
- **Уточнить фильтр:** диалог показывает выбранные примеры и до шести разных фотографий с лицами около границы сходства — среди слабых совпадений и сразу за пределами выдачи. **«Тот же человек»** добавляет пример, **«Другой»** исключает конкретное лицо из совпадений и предложений этого фильтра, **«Пропустить»** откладывает предложение на текущую сессию без изменения выдачи. Если на фотографии есть ещё одно подходящее лицо, фотография остаётся. Нажатие на портрет открывает полный кадр. **«Предложить ещё»** учитывает новые примеры; решения можно отменить, а исключения — снять. **«Применить фильтр»** сохраняет изменения; **«Отмена»** оставляет фильтр прежним. Имена людям приложение не присваивает.
- **Показывать рамки лиц:** флажок справа и в просмотре скрывает только линии рамок. На обнаруженные лица по-прежнему можно нажимать; курсор над ними меняется. Настройка сохраняется между запусками. Кнопка **«Сбросить поиск»** наверху снимает фильтр человека и текстовый запрос, сохраняя папку и период.
- **Период съёмки:** потяните одну из двух точек или выделенную полосу целиком. После отпускания поиск обновляется; Shift + стрелки сдвигают весь период на день. Точные даты можно ввести ниже.
- **Найти похожие:** выберите фотографию и нажмите кнопку справа.
- Двойной щелчок открывает просмотр. Окно можно развернуть обычной кнопкой в заголовке или двойным щелчком по заголовку. В режиме **«Вписать»** фотография подстраивается под размер окна; ручное увеличение и **100%** сохраняют масштаб при изменении размеров. Стрелки переключают кадры, колесо увеличивает изображение, кнопка **100%** загружает оригинальные пиксели. Превью кэшируются с лимитом 20 ГБ.
- Индексация сохраняет положение прокрутки и выбранную фотографию. Когда каталог меняется, над сеткой появляется **«Показать новые фото»**: кнопка показывает актуальные фотографии с текущими фильтрами и не запускает сканирование папок. До нажатия порядок результатов остаётся прежним, в том числе при подгрузке следующих страниц; новые файлы не создают повторов между страницами. Пустой список заполняется автоматически.
- Сканирование добавленных папок, подготовка CPU и модели GPU выполняются одновременно: не нужно ждать окончания всей предыдущей стадии. **Пауза** отменяет ещё не начатые задания, текущие файлы завершаются; очередь и прогресс сохраняются. При перезапуске незаконченный обход папок продолжается с проверкой версий уже найденных файлов.
- **Каталог: просканировано / всего.** Полное число файлов изображений и видео во всех подключённых папках и подпапках подсчитывается отдельно по именам заранее. Пока число неизвестно, показано «Считаю снимки…». Оно не растёт вслед за внесением файлов в базу. После добавления папок пересчитывается весь выбранный набор без повторной обработки прежних фото. Прочитанные и нечитаемые файлы считаются просканированными; подсказка отдельно показывает готовые файлы и ошибки. Если диск недоступен, частичный подсчёт не заменяет сохранённый каталог. Видео считается одним файлом; модельный этап для него завершается после обработки всех выбранных кадров. Прогресс кадров видео показан дополнительно.
- **Состав каталога:** строка над прогрессом показывает число изображений и видео. Кнопка открывает список подключённых папок и распределение по форматам. XMP/AAE не считаются фотографиями. RAW и его JPEG-копия пока считаются двумя файлами. Статус «Подключена со всеми подпапками» в диалоге добавления относится ко всей ветке.
- **Добавить папки:** выберите одну или несколько папок с Ctrl / Shift. Уже подключённые папки и подпапки внутри них пропускаются. Из смешанного набора добавляются и сканируются только новые папки; ошибка одной папки не мешает остальным. При добавлении родителя уже подключённые подпапки повторно не сканируются. Если новых папок нет, индексация не запускается. Самостоятельно весь архив приложение не включает.
- **Поворот фото:** откройте окно рекомендаций и нажмите **«Начать / продолжить проверку»** для всех подключённых фотографий или текущих фильтров. Фоновый процесс сравнивает четыре ориентации по людям, положению тела и геометрии сцены; впечатанная дата исключена из оснований решения. Уже проверенные неизменённые файлы повторно не анализируются. Пауза действует после текущего снимка; очередь и результаты сохраняются при закрытии приложения. Поиск обслуживается между заданиями. Новые добавленные фотографии включаются при следующем нажатии «Начать / продолжить проверку».
- В рекомендациях показаны **«Сейчас» / «После поворота»**, ручной выбор угла и отметка применения. Уверенные рекомендации отмечены заранее, сомнительные находятся в **«Нужна ручная проверка»** и не отмечаются автоматически. **«Повернуть выбранные (N)»** применяет отмеченные рекомендации со всех страниц. Снятие отметки оставляет рекомендацию; **«Исключить эту фотографию»** убирает её из обработки, включая будущие проверки. Исключение можно снять в группе «Исключённые».
- Применение меняет **сами исходные файлы**: JPEG — тег EXIF Orientation без пересжатия изображения, BMP — пиксели с поворотом на 90° / 180° / 270°. JPEG корректно отображается в программах, учитывающих EXIF Orientation. Резервные копии хранятся в `D:\FotoArchiveData\backups\rotations`. После изменения заново строятся миниатюры, эмбеддинги, лица, описания и геоконтекст. **«Отменить последнюю партию»** восстанавливает точные байты и обновляет поиск; доступна после завершения партии. Если файл затем изменён другой программой, отмена его не перезаписывает. **«Отменить ожидающие повороты»** отменяет ещё не начатые изменения, а уже завершённые можно вернуть отдельной кнопкой.
- **Ошибки:** список проблем и повторная обработка. Отключение диска не очищает каталог.
- **Модели:** загрузка закреплённых файлов для первого запуска или восстановления. После загрузки приложение работает без интернета.

Дата фотографий — только EXIF DateTimeOriginal. Если её нет, используется категория «Без даты съёмки». Для видео используется встроенная дата записи QuickTime/creation_time с явной пометкой «метаданные видео». Дата файла и название папки не подменяют дату съёмки; ошибочные часы камеры автоматически не исправляются.

В версии 0.6.0 добавлены RAW через LibRaw, HEIC/HEIF, PNG, GIF, TIFF, WebP, PSD/MPO и видео через FFmpeg. Проверены реальные CR2, ARW, CRW, HEIC, PNG, GIF, TIFF, PSD, MPO, AVI, MOV, MP4, MPG, MOD, MTS и WMV. Для GIF, многокадровых TIFF и MPO используется основной кадр. PSD читается по сохранённому сведённому изображению. RAW отображается по встроенному достаточно большому превью, при его отсутствии — после проявки; масштаб 100% выполняет полную проявку RAW. Редкие неподдерживаемые варианты и повреждённые файлы остаются в счётчике и списке ошибок. Найден один CPT Corel Photo-Paint: для его чтения требуется экспорт в TIFF/PNG; приложение не меняет его. Массовый поворот оригиналов остаётся доступным для JPEG/BMP. Экспорт подборок и именование людей пока не реализованы.

При первом запуске обновления ранее пропущенные форматы автоматически добавляются только из уже подключённых папок. Неизменённые JPEG не проходят модели повторно. Файл видео и индексируемые кадры разделены: каждый кадр имеет время, эмбеддинг, описание, лица и сохранённое состояние каждого этапа. Ошибка одного кадра не останавливает остальные; повтор ошибок не пересчитывает удачные кадры. Изменение файла инвалидирует старые кадры и проходит через сохраняемую очередь обновления индекса.

## Локальная обработка

Эмбеддинги: SigLIP 2 Base, ONNX Runtime DirectML, 768 измерений. Описания и проверка: Qwen3-VL-4B-Instruct Q4_K_M и FP16 vision projector, llama.cpp Vulkan. GPU — основной способ выполнения; приложение не маскирует полный переход на CPU. Некоторые служебные операции ONNX выполняются на CPU.

Координаты GPS, высота и названия мест из EXIF/XMP/IPTC сохраняются отдельно от визуальных векторов. Названия мест получают собственный текстовый эмбеддинг SigLIP и участвуют в поиске. Координаты не подмешиваются числами в визуальный вектор. Локальный справочник GeoNames определяет ближайший город с расстоянием и пометкой приблизительности. Никакие фото или координаты не отправляются в геокодер. Геоданные RAW и встроенные координаты видео также читаются локально; кадры видео наследуют географический контекст исходного файла.

Лица: YuNet и SFace из OpenCV Zoo, обе ONNX-модели выполняются через DirectML. Нормализованные векторы SFace хранятся отдельно от 768-мерных векторов сцены; порог cosine similarity — 0,363. Поиск лиц точный, с фильтрацией до отбора и без жёсткого лимита выдачи. Несколько примеров образуют объединение: для каждого лица берётся максимальное сходство с любым примером, векторы не усредняются. При уточнении просматриваются оценки 0,28–0,48 относительно всего набора примеров; близкие к порогу предложения берутся с обеих сторон, с удалением повторных кадров и почти одинаковых лиц. Никаких решений о личности автоматически не принимается; подтверждения меняют текущий фильтр без переобучения модели.

SQLite хранит каталог, очередь, версии и оригинальные эмбеддинги. LanceDB — восстанавливаемый поисковый индекс; его обновления подтверждаются через SQLite outbox. До 10 тысяч векторов поиск точный, далее IVF_HNSW_SQ для первых результатов. Глубокая прокрутка продолжает точный поток с удалением дублей в SQLite, чтобы не обрезать архив ограниченным набором кандидатов ANN. SQLite принадлежит координатору; порции записей LanceDB обрабатывает один отдельный поток, пока GPU считает следующую порцию. Координатор подтверждает именно записанную ревизию outbox; изменение файла или описания во время записи не теряется. Поиск дожидается текущей записи индекса. Обход файлов работает отдельно с очередью до 256 записей. Подготовка метаданных, миниатюр и SHA-256 выполняется в нескольких процессах CPU; изображение декодируется один раз для метаданных и миниатюры. Число процессов выбирается по физическим ядрам и свободной памяти, не больше 8; на Ryzen 7 8700F — 6 процессов. Очередь ограничена 64 заданиями на процесс, не больше 512 в сумме; между процессами передаются небольшие записи и пути, а не изображения.

GPU получает готовые снимки, пока CPU готовит следующие и обход находит новые. Для эмбеддингов два потока заранее декодируют до 16 снимков, а SigLIP обрабатывает порции до 4 изображений с фиксированными размерами входа DirectML. Подготовленные массивы занимают до 10 МБ, кроме памяти двух декодеров. Эмбеддинги, лица и геоконтекст чередуются в координаторе; одновременно один отдельный поток получает описание от Qwen/Vulkan. Когда описание готово, запускается следующее. SQLite обновляет только координатор, с проверкой версии файла. Дополнительная копия моделей в видеопамять не загружается. Запросы пользователя имеют приоритет: во время проверки условий и уточнения лиц новые фоновые описания не запускаются; запрос к Qwen дожидается только уже начатой фотографии. На паузе заканчивается текущее описание. Внизу окна показаны процессы подготовки и одновременно работающие стадии GPU. Параметр `preparation_workers` в `settings.json` задаёт число CPU-процессов от 1 до 8; `0` — автоматический выбор, изменение применяется после перезапуска. Модельный сервер доступен только локально, с ключом текущего процесса.

Предсказания моделей могут ошибаться, особенно при подсчёте людей на заднем плане, размытых кадрах и отрицаниях. Отсутствие объекта в описании не трактуется как доказательство отсутствия в кадре. Проверка кандидатов не гарантирует нахождение всех совпадений в большом архиве.

git clone https://github.com/aspinozaxxx-lab/FotoArchive.git
cd FotoArchive
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.lock
.venv\Scripts\python.exe scripts\download_models.py
.venv\Scripts\python.exe scripts\gpu_probe.py
.venv\Scripts\python.exe scripts\index_mvp.py
.venv\Scripts\python.exe -m fotoarchive
.venv\Scripts\python.exe -m pytest -q

Известные релевантные примеры не являются исчерпывающей разметкой всех совпадений; для обычного поиска измеряется Hit@20, для проверки условий — precision/recall на размеченных парах.

Команда проверяет каталог, поиск, SigLIP, Qwen, модели лиц, несколько примеров человека, диалоги уточнения и поворота, пропуск существующих папок, затем восстанавливает настройки окна и закрывается. Служебные сценарии v0.3 используют существующие отчёты v0.2 и каталог из 2693 снимков на момент их создания; случайные решения в них нужны только для проверки интерфейса и не сохраняются как разметка людей. `validate_v04.py` анализирует и изменяет только отдельные копии фотографий, проверяет полный цикл поворота и отмены с настоящими GPU-моделями. `--analyze-orientation` при запуске приложения возобновляет рекомендации для уже подключённого каталога; сам по себе этот флаг не меняет оригиналы.

Проверка интерфейса EXE без моделей и рабочей базы: `FotoArchive.exe --ui-smoke-test --data-dir D:\FotoArchiveData\reports\ui-check`. Она использует только искусственные записи. Для обновления только Python-кода при неизменных зависимостях и ресурсах сборка поддерживает `-ExecutableOnly`; такой EXE требует `_internal` от соответствующей полной сборки и не является самостоятельной поставкой.
