# Проверка FotoArchive 0.8.6

## Изменения

Окно читает готовую базу независимо от запуска обработчика. LanceDB, библиотеки
нейросетей, декодеры видео и RAW не импортируются на пути к первому окну.
Qt WebEngine загружается при открытии карты; автоматическая подготовка карты
начинается позже. Новая или несовместимая схема SQLite по-прежнему ожидает миграций.

Последний порядок каталога и группировка стопок сохраняются в одноразовый кэш
на SSD. При совпадении ревизии базы и фильтров страницы читаются прямо из него,
без повторной группировки всего архива. Сведения о каждом файле читаются из
основной SQLite: новые описания и результаты обработки не застывают в кэше.
Изменённый состав, другая группировка или повреждённый кэш вызывают пересборку
в потоке чтения. Снимки, настройки поиска и исходная база для кэширования
не копируются. На текущем каталоге кэш занимает около 24 МиБ; ограничение
одного файла — 128 МиБ. При обновлении кэша старые файлы удаляются; ещё занятые
представлениями файлы повторно проверяются при следующем обновлении.

Сохранение кэша начинается после секунды простоя очереди чтения. Новый фильтр,
страница или закрытие отменяют эту работу. Кэш не нужен для корректности
каталога и не является резервной копией.

Счётчики и справочники восстанавливаются из SQLite. Пересчёт папок начинается
через 15 секунд после готовности обработчика, в отдельном потоке. До полного
окончания проверки остаются прежние числа. Недоступный диск не обнуляет их
и не считается удалением файлов. Проверка обновлений библиотеки остаётся
отдельным действием пользователя.

## Методика и результаты

На реальном каталоге: 126 263 готовых к просмотру файла. До изменения импорт
интерфейса занимал 8,53 с, подготовка первой страницы со стопками — 5,34 с.
После изменения импорт — 0,24 с, чтение страницы из сохранённого порядка —
0,020 с. Первый запуск после изменения состава/формирования нового кэша может
занять больше времени; это измерение не обещает 20 мс для нового запроса.

Проверки запуска выполняются отдельными процессами, с существующим SSD-кэшем
и кэшем Windows; кэш ОС принудительно не сбрасывался. Команда
`--startup-benchmark` запускает настоящий интерфейс Qt и загружает миниатюры,
но не запускает нейросети, не меняет настройки и не обходит исходные папки.
`scripts/validate_startup.py` повторяет эту проверку пять раз. На искусственном
каталоге из 200 000 записей: первый видимый набор миниатюр p95 0,385 с,
создание окна p95 0,302 с. На реальной базе предварительная проверка из
исходников дала 0,68 с до миниатюр. Эти предварительные измерения начинаются
при входе в Python; итоговый скрипт дополнительно передаёт время внешнего
запуска процесса и учитывает загрузчик EXE/Windows. Полное время существования
тестового процесса включает ещё секунду наблюдения и закрытие приложения.

Нагрузочная проверка `scripts/validate_v070_scale.py` выполнялась с параллельной
записью описаний. Итоговый прогон прошёл:

| Проверка | Результат |
|---|---:|
| Чтение прогретого фильтра, p95 | 14,9 мс |
| Переключение фильтра с отрисовкой, p95 | 44,4 мс |
| Событие прокрутки, p95 | 11,8 мс |
| Восстановление после раскрытия стопки, p95 | 518 мс |
| Ошибка положения стопки | 0 пикселей |
| Последний из 100 быстрых переключений | 44,9 мс |
| Интервал событий Qt при переключениях, максимум | 19,3 мс |
| Страниц / изображений в кэше при проверке | 1 / 61 |
| Память процесса с тестовой картой | 476 МиБ |

Первый нагрузочный прогон обнаружил конкуренцию сохранения кэша с анимацией
стопки. Сохранение перенесено на простой, затем проверка повторена.
Offscreen-прогон карты выводил диагностические сообщения Chromium о потере
графического контекста; показатели переключений и стопок измерены до карты.

Полный набор: **269 тестов пройдено за 99,77 с**, одно существующее предупреждение
pywinauto о COM. После финальной правки восстановления настроек обработки
отдельно повторены 7 проверок запуска.

Тесты проверяют запуск при занятом писателе SQLite и недоступных оригиналах,
ожидание миграций, актуальные описания после перезапуска, раскрытие/сворачивание
сохранённых стопок, инвалидацию после удаления, повреждение кэша, отмену его
записи новым фильтром и сохранение счётчиков при фоновом пересчёте.

## Собранное приложение

Содержимое 71 встроенного модуля сверено с текущими исходниками. В EXE прошли
проверки каталога и стопок во всех трёх раскладках, глубокого положения,
добавления страниц, панели сведений и доступности среды Telegram.

Пять запусков итогового EXE на реальном каталоге с внешним отсчётом от создания
процесса: **9,644; 0,546; 0,538; 0,552; 0,551 с** до миниатюр. Все функциональные
проверки прошли, однако строгий порог «каждый запуск до 2 секунд» **не пройден**
из-за первого запуска. Около 9,3 с в первом случае прошли до входа в основной
код Python. Причина этой задержки загрузки пока не установлена; приписывать её
конкретному компоненту Windows без дополнительного профилирования нельзя.
Это ограничение сохраняется и не скрыто в итоговом p95.

Версия 0.8.6 установлена в `dist/FotoArchive` и запущена. В рабочем окне
восстановлены фильтр видео, миниатюры, положение, размеры окна и счётчики
126 546 / 126 546. Отложенное открытие подробной карты проверено через Computer
Use; затем карта скрыта. Локальная и серверная обработка включены, база
сохраняет состояние для следующих запусков. Оригиналы при проверках не изменялись.

Внутренний отчёт обычного установленного приложения: окно 0,227 с, первые
результаты 0,389 с, миниатюра 0,412 с, готовность обработчика 5,643 с; готовность
обработчика не задерживает каталог. Эти величины отсчитываются от входа в
Python и **не включают** описанную выше начальную задержку загрузчика.
